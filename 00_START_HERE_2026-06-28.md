## BLOKIRAJUĆI BUG — nije riješen, treba Claude Code ili dublju dijagnozu

**Simptom:** SVAKI novi `dry_recipe` post (post 3541, 3542, i čak posve prazan test post
3543 s SAMO naslovom, bez ikakvih meta podataka) vraća HTTP 500 na frontend prikazu.

**Potvrđeno NIJE uzrok:**
- Nije naš `_dry_recipe_overrides`/`_dry_verified_process` sadržaj (testirano s i bez)
- Nije registry dopuna u aaa-drycured-registry-01B.php (testirano s i bez)
- Nije WP_DEBUG (testirano uključeno/isključeno)
- Nije memory_limit (puca i na 512MB i na 1GB — eksponencijalni rast, ne fiksna potrošnja)

**Potvrđeno JEST:**
- Greška je `Allowed memory size exhausted` u **`/var/www/html/wp-includes/class-wp-object-cache.php`
  na liniji 363** — WordPress core object cache, ne custom kod
- Nema persistent object cache (Redis/Memcached) instaliran — koristi se default in-memory cache
- Pogađa SVE nove `dry_recipe` postove bez postojećih taxonomy termova, neovisno o meta podacima
- Postojeći stari recepti (npr. post 3308 Istarska kobasica) rade savršeno normalno

**Sumnja (NIJE potvrđeno):** neka funkcija (možda vezana za "related content" po taxonomy-ju,
ili neki recipe-comparison/sličan-proizvod alat) ulazi u petlju `wp_cache_set()` poziva s
unikatnim ključevima kad ne pronađe taxonomy termove za usporedbu, i to neograničeno raste
unutar JEDNOG HTTP zahtjeva (ne ovisi o postojanom cache backend-u).

**Trenutno stanje servera:**
- Post 3541 (Žlomprt) i 3542 (Meso z tiblice) su u `draft` statusu (ne objavljeni javno)
- wp-config.php je VRAĆEN na `define( 'WP_DEBUG', false );` — provjeri da je tako
- Registry dopuna (HR-IS-004, HR-MM-001) je OSTALA u aaa-drycured-registry-01B.php
